## 4. 코드 검수 메모

### 4.1 `NodeRenderer`

`frontend/src/features/documents/NodeRenderer.tsx`는 section 자식 렌더 시 `contentSnapshot`을 그대로 넘기도록 수정되었다. 이전 helper-only 테스트가 놓친 실제 렌더 경로를 `renderToStaticMarkup`으로 검증하므로, 2차 F-04의 재발 방지 수준은 충분하다.

잔여 메모: section 깊이가 매우 깊은 문서에서는 재귀마다 snapshot 인덱스를 다시 만들 수 있다. 현재 규모에서는 차단 이슈로 보지 않는다. 성능 문제가 관측되면 `inlineByNodeId`를 props로 직접 전달하는 리팩터링을 별도 처리하면 된다.

### 4.2 `sanitizeForSave`

`frontend/src/features/editor/sanitizeForSave.ts`는 annotation 목록이 아직 성공 로드되지 않은 경우 원본 doc을 반환한다. 이는 정상 mark 손실보다 stale mark 보존을 선택하는 보수적 동작이다. 저장 시 데이터 손실 방지 관점에서 타당하다.

잔여 메모: annotation query가 에러 상태일 때도 sanitize가 건너뛰어 stale mark가 보존될 수 있다. 이는 비파괴 fallback으로 허용 가능하며, 삭제된 annotation mark의 즉시 정리는 query 복구 후 다음 저장 시 처리된다.

### 4.3 `users_search`

`backend/app/api/v1/users_search.py`가 `db_dependency`를 FastAPI dependency로 받도록 바뀌어 테스트가 DB 경계를 정상적으로 대체할 수 있다. R-A4 테스트의 목적과 구현 경계가 맞아졌다.
