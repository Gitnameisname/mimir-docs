## 3. 절대 규칙 / 정책 준수 확인 (task5-3 §1.2 / §3)

### 3.1 R-A4 — Typeahead ACL 누설 차단

- **viewer_user_id 가 ActorContext 에서만 추출** — 라우터 코드 명시 (`viewer_user_id = actor.actor_id`). query/body 주입 차단.
- **`user_org_roles` JOIN** — viewer 와 같은 org 의 사용자만 SQL 차원에서 격리.
- **응답 모델 강제** — `UserSearchItem` 이 `{user_id, display_name}` 필드만 정의. email/role/status 등 누설 가능성 0 (Pydantic 직렬화 시 자동 제거).
- **단위 회귀**:
  - `test_sql_includes_user_org_roles_join_and_viewer_self_exclude` — JOIN 정합
  - `test_sql_params_include_viewer_id_twice` — viewer_user_id 가 SQL 파라미터로 두 번 (JOIN + 본인 제외)
  - `test_response_only_contains_user_id_and_display_name` — 키 정확성
  - `test_response_model_excludes_email_role_status` — Pydantic 보장
  - `test_other_org_user_not_returned` — multi-org 격리
  - `test_viewer_user_id_must_be_keyword_only` — positional 호출 시 TypeError

### 3.2 SQL Injection 방어

- psycopg2 placeholder (`%s`) — 파라미터 바인딩으로 차단
- ILIKE wildcard escape (`%` `_` `\`) — 추가 방어. 회귀 `test_wildcards_in_query_are_escaped` 검증.

### 3.3 PII 보호 (제24조)

- audit log 가 `q` prefix 자체를 저장하지 않음 — `q_length` + `result_count` 만 (`logger.info` 명시)
- 응답에 raw email / phone 등 PII 없음

### 3.4 Rate Limit

- backend slowapi `60/minute` per user (`_USER_SEARCH_LIMIT`)
- frontend `useUserSearch` 의 150ms debounce — 사용자 빠른 입력 시 호출 횟수 자체를 줄임 (정상 트래픽 보호)

### 3.5 Pre-flight 결정 정합

- **mention 영속화 (C)** plain text — Phase 3 FG 3-3 의 `mentioned_user_ids` 컬럼 재사용. 본문에는 `@display_name` text 만 (mark 별도 신설 안 함)
- **viewer scope** = `user_org_roles` JOIN — multi-org user 자연 지원
