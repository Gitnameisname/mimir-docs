## 1. 합의된 정책 (2026-05-14)

| 결정 | 값 |
|------|----|
| 한국어 mention 이름 기준 | **display_name** — `@홍길동` → users.display_name 매칭 |
| user_id 전송 방식 | **Frontend typeahead 가 user_id 직접 전송 + 본문 정규식 매칭 합집합** (robust) |
| viewer scope 검증 | **backend 가 명시 IDs 도 검증** — R-A4 정합 유지 |

| backward compat | **영문 username 우선** — ASCII 토큰은 username 시도 후 display_name fallback |

## 4. 정책 / 보안 정합

### 4.1 R-A4 (viewer scope ACL 누설 차단)

- frontend 명시 `mentioned_user_ids` → backend `_validate_explicit_mention_user_ids` 가 `user_org_roles` JOIN 으로 viewer scope 강제. 다른 org user_id 주입 시 차단.
- display_name fallback 도 `find_by_display_name_in_viewer_orgs` 가 같은 JOIN 패턴 — viewer scope 안에서만 매칭.
- R-A4 4중 방어 패턴 (FG 5-3) 의 정신 그대로 — 모델/라우터/repository/SQL 모두 viewer scope 검증.

### 4.2 보안 검증 항목

| 위협 | 방어 |
|------|----|
| 악의적 클라이언트가 다른 org user_id 주입 | `filter_user_ids_in_viewer_orgs` SQL 차단 |
| 동일 display_name 충돌 (2명) 으로 잘못된 user 매핑 | LIMIT 2 + 1건일 때만 반환 — 충돌 시 silently skip |
| 정규식 ReDoS | `{1,64}` 상한 + token-by-token 처리. catastrophic backtracking 없음 |
| 본문 길이 폭발 | `MAX_CONTENT_LENGTH = 10_000` 그대로 |
| 동일 user 중복 mention 알림 | `dict.fromkeys` dedupe — 알림 1회만 |
