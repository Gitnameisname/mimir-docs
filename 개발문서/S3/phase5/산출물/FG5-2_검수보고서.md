## 3. 절대 규칙 / 정책 준수 확인 (task5-2)

### 3.1 R-A3 — 본문 편집 차단 없음

- `AnnotationMark.addProseMirrorPlugins` 의 `handleClick` 가 **`return false`** 반환 — TipTap 의 default cursor / selection 동작 보존.
- `event.preventDefault()` 호출 0건. click event propagation 정상.
- syncAnnotationActiveDom 은 시각 마킹 (CSS 클래스 토글) 만 — ProseMirror state 미변경.

### 3.2 R-A1 / R-A2 (ADR §c §b 정합)

- AnnotationMark 의 `inclusive: false` + `excludes: ""` — 4 mark 동시 적용 가능. cleanInvalidAnnotationMarks 회귀 (S2 / S5 시나리오) 통과.
- markNames.ts 정본 사용 — string literal 인라인 0.

### 3.3 sanitize — round-trip 안전

- save_draft 직전 호출 가정 — 실제 호출 지점은 별 라운드 (DocumentEditPage 의 onChange 통합 + valid set 전달). 본 세션은 **헬퍼 함수 (`cleanInvalidAnnotationMarks`)** 와 회귀까지.
- 회귀 7건 (valid 보존 / stale 제거 / 다른 mark 보존 / 4 mark 동시 / 빈 set / immutability / annotation 부재).

### 3.4 cross-stack 정합 (FG 5-1 ADR §f)

| 항목 | frontend | backend | 정합 |
|------|---------|---------|----|
| AnnotationMark name | `markNames.ANNOTATION_MARK_NAME = "annotation"` | annotation 도메인은 별 (`annotations` 테이블 + REST API) — backend mark 직접 처리 안 함 | ✅ |
| data-attr | `data-annotation-id` | (해당 없음 — backend 가 mark attribute 안 봄) | ✅ |
| markdown→ProseMirror (FG 2-6) | (해당 없음 — vault import 는 annotation mark 부여 안 함) | `markdown_to_prosemirror.py` 에 annotation 매칭 부재 (의도) | ✅ |
