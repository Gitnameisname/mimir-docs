# FG 6-2 마이그레이션 가이드 — Retention archive

**작성일**: 2026-05-18

---

## 1. 신규 테이블

| 테이블 | 컬럼 | 인덱스 |
|---|---|---|
| `audit_events_archive` | `audit_events` + `archived_at` | event_type, archived_at, occurred_at |
| `annotations_archive` | `annotations` 핵심 컬럼 + `archived_at` (FK 없음) | document_id, archived_at, resolved_at |

`annotations_archive` 는 `document_id` 에 FK 를 두지 않는다 — archive 테이블은
source 문서가 삭제되어도 보존되어야 하기 때문 (감사 목적).

## 2. 실행 단계

### 2.1 마이그레이션 적용 (P1 승인 후)

```bash
cd backend
ALEMBIC_POSTGRES_USER=mimir_admin alembic upgrade s3_p6_retention_arch
```

idempotent (CREATE TABLE IF NOT EXISTS). 반복 실행 안전.

검증:

```bash
psql -d mimir -c "\d audit_events_archive"
psql -d mimir -c "\d annotations_archive"
```

### 2.2 환경변수 설정

`backend/.env` 또는 docker-compose 안에 추가:

```bash
RETENTION_DOCUMENT_VIEWED_DAYS=7
RETENTION_RESOLVED_ANNOTATION_DAYS=90
RETENTION_BATCH_LIMIT=500
RETENTION_CRON_HOUR=2
# 첫 배포 시 dry-run 켜기:
RETENTION_DRY_RUN=1
```

### 2.3 첫 배포 — Dry-run

1. 배포 후 1~2일 운영. log 에서 다음 패턴 확인:

```
INFO retention_job_start dry_run=True ...
INFO retention_job_complete dry_run=True ... viewed={'candidates': N, 'archived': 0, 'deleted': 0} ...
```

2. 운영자가 candidates 값이 예상 범위에 맞는지 검토.
3. 7일 viewed 가 일 평균 트래픽 × 7일 수준이어야 함. 비정상적으로 크면
   `RETENTION_DOCUMENT_VIEWED_DAYS` 가 짧게 설정된 가능성 검토.

### 2.4 실 운영 전환

```bash
# .env 에서 다음 삭제 또는 0 으로:
# RETENTION_DRY_RUN=

# (선택) cron 시각 조정:
RETENTION_CRON_HOUR=2
```

다음 cron 실행 시 archive + DELETE 실행. log:

```
INFO retention_job_complete dry_run=False ... viewed={'candidates': N, 'archived': N, 'deleted': N}
```

## 3. 롤백 절차

### 3.1 비상 중지

```bash
# scheduler 만 끔 (테이블 보존):
RETENTION_BATCH_ENABLED=false
# 앱 재시작.
```

### 3.2 archive → source 복원

archive 테이블은 source 와 동일 컬럼 구조 (+ archived_at) 이므로 INSERT INTO ...
SELECT 로 역복원 가능. **P1 승인 필수**.

예시 (audit):

```sql
INSERT INTO audit_events (
    id, event_type, occurred_at, actor_user_id, actor_role,
    document_id, version_id, target_version_id, previous_state,
    new_state, action_result, reason, request_id
)
SELECT id, event_type, occurred_at, actor_user_id, actor_role,
       document_id, version_id, target_version_id, previous_state,
       new_state, action_result, reason, request_id
FROM audit_events_archive
WHERE archived_at >= NOW() - INTERVAL '1 day'
ON CONFLICT (id) DO NOTHING;
```
