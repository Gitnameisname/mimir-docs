## 1. 종합 판정

**조건부 통과 / 공식 종결 보류**

Phase 7 변경 코드의 핵심 단위 테스트는 통과했다. `app.cache.namespace`, `app.cache.policy`, `app.cache.pubsub`, `viewed_throttle`, `scope_profile_policy`의 1차 구현은 대체로 의도한 방향과 맞고, 함수도서관도 갱신되어 있다.

다만 `Phase 7 개발계획서.md` §5.1~5.2가 요구한 extended 완료 게이트 중 일부가 아직 단위 mock 수준에 머물러 있다. 특히 FG 7-3의 `scope_profile_policy`는 원 계획의 “Valkey 장애 시 fail-closed(cache 비움 -> DB 재조회)”와 달리 “process-local TTL 30초 유지 + broadcast best-effort”로 구현되어 있다. 이는 설계 변경에 해당하므로 공식 종결 전 ADR 또는 명시적 human approval이 필요하다.

## 2. 주요 발견 사항

### [P1] FG 7-3 fail-closed 요구와 구현이 불일치

- 계획서 요구: `Phase 7 개발계획서.md` §1.2 / §2.1은 `scope_profile_policy invalidate`를 보안 관련 fail-closed로 정의한다. Valkey 장애 시 캐시를 비우고 다음 호출에서 DB를 재조회해야 한다.
- 현재 구현: `backend/app/services/scope_profile_policy.py`는 Valkey 장애 / disabled 시 broadcast만 skip하고 process-local TTL 30초를 유지한다. 문서 주석도 “다른 워커는 최대 30s stale 허용”이라고 명시한다.
- 영향: admin이 `expose_viewers=false`로 변경한 직후 Valkey 장애 또는 subscriber 장애가 있으면 다른 워커가 최대 30초 동안 stale `true`를 반환할 수 있다. viewers 노출 정책이 보안/프라이버시 게이트라면 원 요구 대비 완화다.
- 필요 조치: strict fail-closed로 구현을 맞추거나, `scope_policy`의 fail-open TTL 허용을 ADR + @최철균 승인으로 계획 변경 처리해야 한다.

### [P1] 공식 완료 게이트가 실제 통합/chaos 검증 없이 부분 충족 상태

계획서 §5.1~5.2는 다음을 완료 기준으로 둔다.

- Valkey off 환경에서 fallback 회귀
- 의도적 connection drop chaos 테스트
- AUTH 없는 pub/sub 클라이언트 거부
- admin PATCH 후 모든 워커 < 1초 invalidate
- Phase 1~6 모든 회귀 녹색

현재 검증은 대부분 mock 단위 테스트다. `Phase7_1라운드_종결보고서.md`도 실제 컨테이너 chaos, AUTH/ACL, latency 측정을 별 산출물로 남겼다. 따라서 “코드 1차 완료”는 가능하지만 “Phase 7 공식 종결” 또는 “S3 1라운드 전체 종결”의 증거로는 부족하다.

### [P2] subscriber 자동 재구독 부재

`Subscriber.start()`가 startup 시 Valkey disabled / subscribe 실패를 만나면 `False`를 반환하고 종료한다. 이후 Valkey가 회복되어도 자동 재시작 경로가 없다. `_run()` 루프 내부 오류에는 1초 백오프가 있지만, 초기 subscribe 실패나 startup disabled는 복구하지 않는다.

운영 가이드의 “Valkey 재기동 후 1분 내 cluster-wide invalidate 정상” 권고를 충족하려면 heartbeat/retry 또는 운영 재시작 절차가 필요하다. 현재 종결보고서의 O-7-6으로 남아 있으므로 공식 운영 전 보완 또는 명시적 운영 제약으로 고정해야 한다.

### [P3] namespace segment의 `:` 처리 주석과 구현 불일치

`backend/app/cache/namespace.py` 주석은 `:`를 segment 구분자로 보고 escape한다고 설명하지만 `_quote_part()`는 whitespace/null만 치환하고 `:`는 그대로 둔다. 현재 주요 호출자는 UUID 계열이라 즉시 위험은 낮지만, `make_key()` / `make_channel()`은 공용 유틸이므로 향후 colon 포함 입력에서 segment 경계가 모호해질 수 있다. 테스트도 없다.

## 5. 권고

1. FG 7-3 fail policy를 결정한다: strict fail-closed 구현 또는 ADR + human approval로 best-effort TTL 정책 승인.
2. Valkey chaos 산출물을 추가한다: disabled boot, connection drop, restart/reconnect, 4-worker SETNX/invalidate, AUTH/ACL 거부.
3. subscriber startup 실패 후 재구독 전략을 구현하거나, 운영 절차상 “Valkey 회복 후 backend restart 필요”로 명시한다.
4. 전체 unit 4건 실패를 Phase7 공식 종결 전 수정하거나, 사전-존재 실패 예외 기록을 Change Boundary에 남긴다.
