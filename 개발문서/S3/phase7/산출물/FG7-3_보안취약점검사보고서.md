## 3. 발견 / 권고

### 3.1 발견 — None (1차)

신규 보안 위협 발견 없음. 모든 OWASP / DoS / 인가 항목 통과.

### 3.2 권고 (운영 영역)

- **R-1**: Valkey ACL 로 pub/sub 채널 접근 제한 (FG 7-1 가이드 §3.3). 본 코드는 ACL 없이도 안전 동작.
- **R-2**: 메시지 폭주 모니터링 (Valkey `MONITOR` 또는 pub/sub channel count). 운영자 dashboard 추가 권장 — 별 산출물.
- **R-3**: subscriber thread 재시작 정책 — 본 Task 는 단순 daemon thread. Valkey 장애 후 회복 시 자동 재구독 안 함. 운영자가 정상 회복 후 워커 재시작 필요. 자동 reconnect 는 별 라운드 (heartbeat + retry backoff).

## 4. Race / Concurrency 상세

### 4.1 `invalidate_cache` 의 lock 범위

```python
with _lock:
    # local cache 비움
if not broadcast: return
# publish (lock 외부)
publish_invalidate(...)
```

- lock 안에서 publish 하지 않음 — Valkey 응답 지연이 다른 워커의 cache 접근 차단하면 안 됨
- 이론적 race: publish 전에 다른 thread 가 cache 채움 가능 → 다음 broadcast 가 이 entry 비울 것 (eventually consistent)
- TTL 30s 가 backstop — 최악 30s stale

### 4.2 subscriber loop 보호

- `_stop_event.wait(1.0)` — error backoff 시에도 즉시 종료 응답
- get_message timeout=1.0 — stop_event 응답성
