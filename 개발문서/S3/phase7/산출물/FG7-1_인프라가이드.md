# FG 7-1 인프라 가이드 — Valkey 운영 (운영자 대상)

**작성일**: 2026-05-18
**대상**: 운영자 (인프라 측), 환경별 배포 책임자
**선행**: Task 7-1 코드 변경 머지

---

## 1. 환경변수

| 변수 | 기본값 | 의미 |
|---|---|---|
| `VALKEY_HOST` | `localhost` | Valkey 호스트. **빈 문자열 → disabled (폐쇄망)** |
| `VALKEY_PORT` | `6379` | Valkey 포트 |
| `VALKEY_PASSWORD` | `""` | Valkey AUTH 토큰 |
| `VALKEY_USER` | `""` | Valkey ACL 사용자 (선택) |
| `VALKEY_DB` | `0` | logical DB |
| `VALKEY_DISABLED` | `""` | `1` / `true` / `yes` / `on` 중 하나면 강제 disable |
| `VALKEY_NAMESPACE` | `""` (자동) | 미설정 시 `mimir:<environment>`. 강제 override 가능 (예: `mimir:prod`) |
| `VALKEY_FAIL_OPEN_FEATURES` | `""` | comma-separated feature override (default fail-open) |
| `VALKEY_FAIL_CLOSED_FEATURES` | `""` | comma-separated feature override (default fail-closed). **둘 다 지정 시 fail-closed 우선** |

## 2. 배포 모드

### 2.1 표준 (dual-process docker-compose)

```yaml
# docker-compose.yml
services:
  valkey:
    image: valkey/valkey:8
    command: >
      valkey-server
      --maxmemory 256mb
      --maxmemory-policy allkeys-lru
      --requirepass ${VALKEY_PASSWORD:?}
  backend:
    environment:
      VALKEY_HOST: valkey
      VALKEY_PASSWORD: ${VALKEY_PASSWORD:?}
```

### 2.2 폐쇄망 — Valkey 자체 운영 (단일 노드)

```yaml
services:
  valkey:
    image: valkey/valkey:8  # 사내 mirror 권장
    command: >
      valkey-server
      --requirepass ${VALKEY_PASSWORD:?}
      --maxmemory 256mb
  backend:
    environment:
      VALKEY_HOST: valkey
      VALKEY_PASSWORD: ${VALKEY_PASSWORD:?}
      VALKEY_NAMESPACE: mimir:onprem
```

### 2.3 폐쇄망 — Valkey 미운영 (단일 워커 / 비최소 환경)

```bash
export VALKEY_DISABLED=1
# 또는
export VALKEY_HOST=""
```

이 모드에서는:
- `app.cache.get_valkey_or_none()` → `None`
- `viewed_throttle.should_emit_view()` → 워커별 LRU (Phase 3 동작 그대로)
- `scope_profile_policy` → process-local TTL 30s (Phase 3 동작 그대로)
- `response_cache` → in-memory fallback (Phase 13 동작 그대로)
- pub/sub broadcast → silent skip

cluster-wide 일관성은 보장 안 되지만, **단일 워커 / 단일 노드 환경에서는 차이 없음**.

## 3. Pub/Sub 보안 (R-I3)

### 3.1 채널 명명 규칙

| 채널 유형 | 형식 | 용도 |
|---|---|---|
| cluster-wide | `mimir:<env>:cache:invalidate:<feature>` | 전체 워커 broadcast (tenant 격리 무관) |
| tenant-scoped | `mimir:<env>:tenant:<org_id>:cache:invalidate:<feature>` | 특정 org 만 broadcast |

### 3.2 운영자 책임

- `requirepass` 또는 ACL 로 인증 강제
- 다른 시스템과 Valkey 공용 시 **별 namespace** 사용 (`VALKEY_NAMESPACE=mimir:prod` 명시)
- pub/sub 채널 ACL 권한:
  - 백엔드 워커: 자기 `mimir:<env>:` prefix 채널만 SUBSCRIBE / PUBLISH
  - 다른 tenant 채널 접근 금지 (운영자 정책으로 강제)

### 3.3 Valkey ACL 예시 (운영자 설정)

```redis
ACL SETUSER mimir-worker on >${VALKEY_PASSWORD} \
    ~mimir:prod:* \
    &mimir:prod:* \
    +@read +@write +@pubsub -@dangerous
```

본 코드는 ACL 미설정 환경에서도 동작 (silent fail-open). ACL 은 운영 인프라 측 정책.

## 4. Fail-Open / Fail-Closed 정책 (R-I2)

| Feature | Default | 이유 |
|---|---|---|
| `viewed_throttle` | fail-open | 감사 dedup — 가용성 우선. Valkey 장애 시 워커별 LRU |
| `rate_limit` | fail-open | rate-limit — 가용성 우선. slowapi swallow_errors |
| `scope_policy` | fail-closed | 정책 게이트 — 보안 우선. Valkey 장애 시에도 process-local TTL 30s 유지 (FG 7-3 §3.4) |
| `response_cache` | fail-open | 응답 캐시 — 성능. Valkey 장애 시 in-memory fallback |
| `admin_settings` | fail-open | 설정 캐시 — admin PATCH 후 다음 호출 자동 재로드 |

운영자가 보안 강화 시:
```bash
export VALKEY_FAIL_CLOSED_FEATURES=scope_policy,viewed_throttle
```

운영자가 가용성 우선 시:
```bash
export VALKEY_FAIL_OPEN_FEATURES=scope_policy
```

**둘 다 지정 시 fail-closed 우선** (보수 default).

## 5. 헬스체크

`GET /api/v1/admin/system/health` 응답에 `valkey` 항목 포함 — 기존 admin 라우터 (Phase 13 도입) 그대로 사용.

```json
{
  "valkey": {
    "status": "HEALTHY",
    "latency_ms": 0.4,
    "used_memory_human": "12.34M"
  }
}
```

disabled 모드 시 `status: "DOWN"` + `error: "..."` 또는 `"DISABLED"` (운영자가 의도한 상태).

## 6. Chaos / 폐쇄망 회귀 권고 (별 산출물)

| 시나리오 | 검증 항목 |
|---|---|
| `VALKEY_HOST=""` 시 백엔드 기동 | 5xx 없음, 응답 정상 |
| Valkey 컨테이너 정지 → 30분 운영 | rate-limit / dedup 정상 (LRU fallback) |
| Valkey 재기동 후 1분 내 | cluster-wide invalidate 정상 |
| 다중 워커 (4 우산) + admin PATCH | 1초 안에 모든 워커 invalidate |

위 ≥ 4 시나리오를 chaos test 로 자동화 — 별 산출물 (Codex 또는 운영자).

## 7. 운영 점검 체크리스트

- [ ] 환경별 `VALKEY_PASSWORD` 가 .env / secret manager 에 분리되어 있는가
- [ ] `mimir:<env>:` namespace 가 다른 시스템과 충돌하지 않는가
- [ ] Valkey 인스턴스 `maxmemory` 설정 — 256MB 이상 권장
- [ ] `maxmemory-policy=allkeys-lru` 설정 — eviction 가용
- [ ] 백엔드 로그에 `Valkey connected: ...` 메시지 확인 (또는 `Valkey disabled` if 의도)
- [ ] 폐쇄망의 경우 docker-compose 의 valkey 서비스가 같은 네트워크에 있는가
