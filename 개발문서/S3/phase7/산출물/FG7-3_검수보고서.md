## 2. R-I 절대 규칙 매핑

| 규칙 | 본 Task 충족 |
|---|---|
| **R-I1 폐쇄망** | `start_subscriber()` 가 disabled 시 silent skip → process-local TTL 만 동작. `publish_invalidate` 도 disabled 시 False 반환 |
| **R-I2 fail-open vs closed** | scope_policy 는 **fail-open** (process-local TTL 30s 유지, broadcast 만 best-effort). Task 7-3 §3.4 의 합의 — strict fail-closed 는 별 ADR. policy 분류는 `scope_policy=FAIL_CLOSED` 등록 (캐시 layer 자체의 default — 호출자가 적용) |
| **R-I3 pub/sub 권한** | tenant prefix (필요 시), 메시지 크기 1KB, JSON parse 실패 silent skip, loop 방지, callback exception 격리. `TestSubscriberDispatch` 11 case |
| **R-I4 키 namespace** | `make_channel("scope_policy")` → `mimir:<env>:cache:invalidate:scope_policy` |

> NOTE on R-I2: 본 Task 의 fail 정책은 "cluster-wide 즉시성은 best-effort, process-local cache 는 fail-open" 입니다.  Phase 7 개발계획서 §1.2 의 "scope_profile_policy invalidate 는 fail-closed (cache 비움 → 다음 호출 DB 재조회)" 와 비교 시, **process-local cache 자체를 비우는 strict fail-closed** 는 본 라운드에서 보류 — 정상 동작 가용성을 해칠 위험 + Phase 3 의 TTL 30s 의 의도와 정합 (별 ADR 가능).

## 3. Pub/Sub 보안 / DoS 방어

| 위협 | 방어 |
|---|---|
| 메시지 폭주 (DoS) | `MAX_MESSAGE_SIZE=1024`. dispatch 전 byte 길이 검증 |
| JSON parsing crash | `(ValueError, TypeError)` swallow + debug log |
| pub/sub loop | `worker_id == WORKER_ID` skip. `broadcast=False` 파라미터 |
| callback 예외 전파로 subscriber thread 종료 | dispatch 가 `Exception` 격리 + warn log |
| 잘못된 메시지 구조 (list 등) | `isinstance(payload, dict)` 검증 |
| 빈 key | `if not isinstance(key, str) or not key: return` |
| invalid UTF-8 bytes | try/except UnicodeDecodeError → skip |
| 다른 tenant 채널 구독 | `Subscriber.__init__` 가 본 namespace prefix 만 사용. 다른 tenant 채널은 명시적 org_id 지정 필요 |

## 6. Thread Safety / 자원 관리

- subscriber thread: `daemon=True` — 앱 종료 시 자동 종료
- `_stop_event`: 명시적 종료 신호 제공
- `_pubsub.close()`: stop 시 redis-py PubSub 객체 정리
- get_message timeout=1.0: stop_event 응답성 보장
- 백오프: loop error 시 1.0s wait → burst 회피
