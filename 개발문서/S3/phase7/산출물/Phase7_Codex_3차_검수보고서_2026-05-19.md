## 2. 발견 사항

### [P1] ADR이 아직 승인 완료처럼 읽힌다

- 위치: `docs/개발문서/S3/phase7/산출물/ADR-FG7-3-fail-closed-정책.md`
- 문제:
  - 상단 상태가 `Proposed → Accepted`로 되어 있다.
  - 작성자 줄에 `승인: @최철균 (P1)`가 남아 있다.
  - 같은 문서 안에는 “@최철균 P1 승인 잔여”라고도 적혀 있어 상태가 모순된다.
- 영향:
  - 사용자가 이전 승인 발화는 오발송이라고 정정했으므로, 이 문구는 실제 승인 상태와 불일치한다.
  - 제45조 / 제46조 Approval Gate와 Approval Binding을 오염시킬 수 있다.
- 필요 시정:
  - ADR 상태를 `Proposed` 또는 `Pending Approval`로 정정.
  - `승인: @최철균 (P1)`를 `승인: pending (@최철균 P1 승인 필요)`처럼 바꿀 것.
  - 변경 이력에도 “승인 대기” 상태임을 명시.

### [P2] 신규 namespace 회귀 테스트에 no-op assertion이 포함됨

- 위치: `backend/tests/unit/cache/test_namespace.py:67`
- 문제:
  - `assert ... or True` 형태라 항상 통과한다.
  - 해당 줄은 “키 충돌 회피 검증”이라고 설명하지만 실제 검증을 수행하지 않는다.
- 영향:
  - `AUTOMATION.md` Failure Modes가 금지한 no-op assertion 패턴에 해당한다.
  - Codex 2차 P3 시정의 핵심인 `:` segment sanitize 회귀 신뢰도를 낮춘다.
- 필요 시정:
  - 해당 줄을 제거하거나 실제 검증으로 대체한다.
  - 예: `assert key_a != key_b`, `assert key_a == "mimir:test:viewed:user_1:a"`, `assert key_b == "mimir:test:viewed:user:1_a"`처럼 기대 키를 명시한다.
