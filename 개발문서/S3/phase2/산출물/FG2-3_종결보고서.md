## 3. 절대 규칙 / 정책 준수 확인

### 3.1 R2 ACL 단일 결정점

- `wikilink_resolver.resolve_wikilinks` 가 자체 ACL 결정 안 함 — `viewer_scope_profile_ids` keyword-only required + `DocumentLinksRepository.find_candidates_by_title` 의 IN 필터로 위임 (FG 2-2 의 `document_ids_for_tag` 와 동일 패턴).
- `/backlinks` / `/resolve` 라우터는 `_resolve_viewer_scope_profile_ids(actor)` 헬퍼 (documents_service 정본) 사용 — bypass role (ORG_ADMIN/SUPER_ADMIN) 자동 스킵.
- `/links` 라우터는 `admin.read` 권한 게이트 — viewer 호출 시 거부.

### 3.2 존재 유출 방지 (R-A4 정합)

- viewer Scope 외 문서가 같은 제목을 가져도 후보로 들어가지 않음 — `missing` 으로 관측 (회귀: `test_wikilink_resolver_fg23::test_other_scope_document_not_leaked`)
- `/backlinks` 가 도착 문서 자체에 대한 ACL 검증 — viewer 가 못 보면 404 (존재 유출 방지)
- `/resolve` 응답이 doc id + title + updated_at 만 노출 — scope_profile_id / owner / 다른 메타데이터는 절대 응답에 포함하지 않음

### 3.3 NFC 정규화 (R-04)

- `wikilink_resolver.normalize_title` 가 NFC + strip 적용. 한글 조합형/완성형 동일 입력 시 같은 문서로 resolved (회귀: `test_combined_vs_decomposed_korean`)
- `/resolve` 라우터도 입력을 NFC 정규화 후 backend 전달

### 3.4 트랜잭션 규약 (작업지시서 상호검증 §7)

- `with get_db() as conn:` 블록 안에서 nodes → tags → **wikilinks** → annotation_anchoring 순서 강제. `snapshot_sync_service.py` docstring 에 명시. draft_service / agent_proposal_service 두 호출 지점 모두 동일 chain.

### 3.5 뷰 ≠ 권한 정합 (S2 ⑥)

- `document_links` 테이블 자체는 ACL 결정에 영향 없음 — Alembic up SQL 의 docstring 명시.
- 읽기 시점 (`/backlinks`) 마다 viewer Scope 자동 필터 — 저장 시점 `resolved_status` 는 작성자 Scope 힌트일 뿐 (task2-3.md §5 line 158 의 "viewer 컨텍스트 기준 재해석" 정신).

## 4. 보안 회귀 (task2-3.md §9 보안 보고서 항목 흡수)

### 4.1 회귀 시나리오 (단위)

| ID | 시나리오 | 위치 |
|----|---------|-----|
| ACL-1 | viewer (scope-A) 가 scope-B 비공개 문서 제목으로 `[[...]]` → missing | `test_wikilink_resolver_fg23::test_other_scope_document_not_leaked` |
| ACL-2 | 동일 제목 + 다른 scope → 각 viewer 의 자기 scope 결과만 | `test_same_title_different_scopes_resolved_within_scope` |
| ACL-3 | 빈 scope → 모두 missing | `test_empty_scope_returns_no_candidates` |
| ACL-4 | admin (None scope) → 필터 skip | `test_none_scope_skips_filter_admin` |

### 4.2 회귀 시나리오 (통합 — **별 라운드 미진행**)

다음 통합 회귀는 본 세션 컨텍스트 한계로 미작성. 운영자 P1 승인 + Alembic 적용 후 별 라운드에서 작성 권장.

- IT-1: 저장 → `document_links` 행 동기화 (resolved/missing 혼합) — task2-3.md §7 "integration ≥ 5"
- IT-2: B 의 비공개 문서 제목으로 A 가 `[[]]` 입력 → A 의 응답에 missing pill, B 정보 누설 0
- IT-3: 두 organization 의 동일 제목 — 각 viewer 가 자기 scope 결과만 (B6 회귀)
- IT-4: 본문 변경으로 wikilink 추가/삭제 → `replace_for_document` 동작 검증
- IT-5: 순환 링크 (A→B→A) — 양방향 backlink 정상

### 4.3 추가 보안 검토 (잠재 위험)

- **prompt injection 회귀** — wikilink raw_text / title 에 `ignore previous` 같은 페이로드가 들어와도 응답이 plain text 만 반환. envelope 표준 (Phase 4 FG 4-1) 적용은 본 FG 외 — MCP 표면이 아닌 REST.
- **rate limiting** — `/resolve` 는 typeahead 빈번 호출. SlowAPI 또는 동등 미들웨어가 documents 라우터 차원에서 적용된다고 가정 (별 검증 — Pre-flight §2.8 참조).
- **timing attack — 다른 scope 문서 존재 여부 누설** — `find_candidates_by_title` 가 IN 필터로 빠르게 0건 반환하므로 응답 시간 차이는 작음. 통합 회귀에서 정량 측정 권장.
