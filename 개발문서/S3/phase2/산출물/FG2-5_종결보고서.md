## 3. 절대 규칙 / 정책 준수 확인

### 3.1 화이트리스트 강제 (R-01)

- `SavedViewFilter` / `SavedViewSortItem` / `SavedViewCreateRequest` / `SavedViewUpdateRequest` 모두 `extra="forbid"` — 임의 키 거부.
- 단위 회귀 3건 (filter / create / sort 임의 키 거부)

### 3.2 owner_id 마스킹 (R-02)

- `SavedViewResponse` 가 `owner_id` 필드 자체 미포함 — 응답 직렬화 시점에 자동 제거.
- 단위 회귀 1건 (`test_owner_id_not_in_response`)
- 라우터의 `_to_response` 헬퍼가 SavedViewResponse 로 직렬화 — 모든 GET 응답이 마스킹.

### 3.3 owner 격리 (PATCH/DELETE)

- `repository.update/delete` 의 SQL `WHERE id=? AND owner_id=?` 강제 — 다른 사용자가 view_id 만 알아도 수정/삭제 불가
- service 가 결과 None/False 시 404 ApiNotFoundError → **존재 유출 차단**
- 단위 회귀 2건 (`test_update_other_owner_returns_not_found`, `test_delete_other_owner_returns_not_found`)

### 3.4 상한 50 / UNIQUE (owner_id, name) (R-03 / R-04)

- service `create` 진입 시 `count_by_owner` 검증 → 50 도달 시 409
- DB UNIQUE 제약이 같은 이름 중복 차단 → psycopg2.UniqueViolation → 409
- 단위 회귀 1건 (상한 도달 → 409)

### 3.5 ACL 재필터 (task2-5.md §2.1 (5))

- 본 서비스는 documents ACL 결정점이 아님. view 적용 시 `viewToQueryString` 으로 URL 복원 → DocumentListPage 가 documents API 호출 → **viewer 의 ScopeProfile 로 재필터** (FG 2-0 의 정본 헬퍼).
- frontend 의 view 적용 안내 배너에 "권한 안의 결과만 표시됩니다" 명시 — 구체 건수 / 누락 항목은 노출 안 함 (R-A4 정합).

### 3.6 어휘 단일 정본 (S2 ⑥)

- backend `SavedViewLayout` Literal — `app.schemas.saved_views`
- frontend `SavedViewLayout` — `lib/api/saved_views.ts` (`DocumentLayout` (FG 2-4 layout.ts) 와 동일 어휘)
- DB CHECK 제약 — `saved_views.layout IN ('list','tree','cards','graph')`
- **3 곳 동기화 의무** — 변경 시 동시 수정 + 검수보고서 기록.
